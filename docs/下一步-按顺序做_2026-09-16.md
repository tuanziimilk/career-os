## 第 2 步 · 迁移 SQL 的预检（约 2 分钟，**很可能直接销掉**）

**为什么要做**：题目 id 从「位置型」（`m1-q7`）改成了「内容型」（`q-a1b2c3d4`）。
如果你**以前在 03 题库页标记过**「会 / 不会」，那些记录还挂在旧 id 上，
需要迁移一次；**如果从没标记过，这一步直接跳过**。

### 怎么做

打开 Supabase → SQL Editor，**只跑这一句**：

```sql
select count(*) as 待迁移行数
from career_question_practice
where user_id = auth.uid() and question_id ~ '^m[0-9]+-q[0-9]+$';
```

**看结果**：

- **返回 0** → 完事了，关掉。`web/scripts/out/migrate-question-ids.sql` 可以删掉，
  这一条从此销账
- **返回 > 0** → 打开 `web/scripts/out/migrate-question-ids.sql`，
  先扫一眼文件里那些 `-- 旧 id → 题干` 的注释行，确认对得上，
  再把「第 2 步」那一整段（`begin;` 开始）贴进 SQL Editor 执行

### 验收

再跑一次上面那句预检，返回 0。

### 出错了怎么办

迁移脚本是**可重复执行**的（第二次匹配不到旧 id，影响 0 行），所以跑重了不要紧。
它包在 `begin; ... commit;` 里，中途失败会整体回滚。

## 第 3 步 · 采集前的一次性准备（约 10 分钟）

⚠️ **这一步必须在采集之前做，而且顺序不能反。**

去重键从裸 `12345678` 改成了 `boss:12345678`。你本地那 2 条记录用的是旧键，
云端那 2 条也是。**换了新版扩展再删，墓碑记的是新键、云端那条是旧键，对不上，
那两条就只能进 Supabase 后台手动清了。**

### 3.1 先删掉现有的 2 条（用**插件弹窗**，不是工作台）

1. 点浏览器工具栏的插件图标，打开弹窗
2. 列表里每条右侧有删除按钮，两条都删掉
3. 点「同步到云端」—— 让删除墓碑推上去，把云端那两条也清掉

> 为什么是弹窗不是工作台：弹窗的删除走的是「本地删 + 写墓碑 + 下次同步删云端」
> 三件事一起做的路径，而此刻墓碑记的还是旧键，正好和云端对得上。

### 3.2 装新版扩展

1. 打开 `chrome://extensions`
2. 找到 JD Insight，点「重新加载」（🔄 图标）
3. 确认版本号变成 **2.2.0**

## 第 4 步 · 采满 100 条（分 3~4 次，别一个下午刷完）

分次的理由：BOSS 的 DOM 会变，一次性刷完的话，万一中途选择器失效，
你要到最后才发现，而前面几十条的公司名可能已经是空的了。
分次采，每次开弹窗扫一眼有没有「公司名没抓到」。

**采到 20 条时停一下**，数弹窗里有几条带虚线边的「＋薪资」（= 待补）：

- 超过 6 条（30%）→ 先告诉我，可能要把补录做成批量流程再继续

## 第 5 步 · 填 `analyzer/config.py` 的 `MY_PROFILE`（采满之后）

**为什么现在不做**：`MIN_SAMPLE = 10`。在 10 条语料之前，缺口章无论如何都会降级成
只给原始计数。所以填了也看不到效果。

### 怎么做

打开 `analyzer/config.py`，找到 `MY_PROFILE`。现在是 4 条占位：

```python
MY_PROFILE = {
    "产品基本功": "🟢 示例：主导过某后台重构，PRD + 高保真原型 + 字段级规格",
    "数据能力": "🟢 示例：SQL / 漏斗分析 / 指标定义",
    "RAG / 检索": "🟡 示例：做过 Embedding 检索，缺生成侧",
    "对话式产品": "🔴 示例：没做过多轮对话产品",
}
```

**把「示例：」去掉，换成真实自评。** 规则：

- 组名必须和同文件 `GROUPS` 里的**逐字一致**（共 36 组，不用全填，没填的显示 `—`）
- 前缀三选一：`🟢` 有真实项目支撑 / `🟡` 概念懂但缺实操 / `🔴` 空白
- **只要还含「示例」二字，闸门就会拒绝输出缺口章** —— 这是 P0 加的，
  防的是「模板占位被当成真实能力印进报告」那次事故
