## 6. ⚠️ 唯一还没处理的：脱敏词表本身泄露了它要脱敏的东西

```
web/scripts/import-content.mjs:48   [/<前雇主全称>/g, "某跨境优惠券平台"]
web/scripts/leaks.mjs:53            [/<前雇主全称前四字>/, "前雇主全称。REDACT 漏了才会出现"]
web/scripts/check-diagrams.mjs:158  LEAK_WORDS = [/<前雇主全称>/, /<内部系统缩写>/, /<内部平台代号>/i]
```

**产物是干净的，机制也在正常工作 —— 但机制本身在公开仓库里，而且写出了完整的映射关系。**
读这三行就能知道：前雇主全称、一个内部系统缩写、一个内部平台代号
（最后那个顺带解释了前面那个项目文档编号的前缀是什么）。

这和本文其他条目**性质不同**：其他条目是「抄进来的东西可以换掉」，
而词表**必须有明文才能匹配**，改写就等于失效。

**建议的解法**（是设计改动，需要先拍板）：

1. 新建 `web/scripts/redact.local.mjs`，加进 `.gitignore`，装真实词表
2. 提交一份 `redact.example.mjs` 说明结构，内容全是占位
3. 三个脚本改成 import 本地文件；**文件缺失时必须大声报错退出**，
   不能静默跳过 —— 否则就是又一个「扫零个文件然后报告全部通过」
   （`check-line-endings.mjs` 在合并当天刚踩过这个坑）

> 另：这个名字**已经在 git 历史里**。改了之后新提交干净，但翻历史仍能看到。
> 前雇主实名这一条，我认为比公司名那批更值得考虑 `git filter-repo` 改写历史。
