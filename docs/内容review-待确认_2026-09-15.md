### 模块 M1 · RAG

#### [m1-c1] 为什么需要 RAG(先讲清"痛点")

大模型(LLM)有三个硬伤:
1. **知识过时/缺失**:只学过训练截止日之前的公开数据,不知道你公司的商家库、你昨天写的文档、今天的新闻。
2. **会幻觉**:不知道也硬答,一本正经编造。
3. **不可溯源**:给个答案但说不清依据,业务上不敢用。
**RAG = Retrieval-Augmented Generation(检索增强生成)**:回答前,先从"知识库"里**检索**出最相关的资料,再把资料塞给 LLM,让它**基于资料生成**答案并给出处。
> 🎯 类比一:**开卷考试**。闭卷靠记忆容易瞎编;RAG 是先翻书找到相关那几页,再照着答——准、还能标页码。
> 🎯 类比二(贴你背景):RAG 里"**找相关资料**"这一步,就是你做过的 **query 与页面语义相似度匹配**。你早就会 RAG 最核心的检索环节了。
**RAG 解决的本质**:让通用大模型能用上**私有 + 最新**数据,同时**压制幻觉**、**可溯源**。

#### [m1-c3] 关键术语(先建立词汇,后面才看得懂细节)

| 术语 | 通俗解释 |
|---|---|
| **Embedding(嵌入/向量化)** | 把一段文字变成一串数字(向量),表示它的"语义坐标"。意思接近→向量接近。 |
| **向量(vector)/维度** | 那串数字。text-embedding-3-small 是 1536 维,large 是 3072 维。 |
| **余弦相似度(cosine)** | 衡量两个向量方向有多接近,-1~1,越接近 1 越相似。检索排序就靠它。 |
| **向量库(vector DB)** | 专门存向量、并能快速找"最相似 Top-K"的数据库(FAISS/Chroma/Milvus/pgvector…)。 |
| **chunk(块)/chunking** | 把长文档切成的小段。 |
| **Top-K** | 检索时取相似度最高的前 K 个块(常 3~8)。 |
| **rerank(重排)** | 对初检回来的块用更精的模型再排一次序。 |
| **上下文窗口(context window)** | LLM 一次能"读"的最大 token 数,塞太多会超限/变贵。 |
| **幻觉(hallucination)** | 模型编造与事实/资料不符的内容。 |
| **混合检索(hybrid)** | 向量检索(语义)+ 关键词检索(BM25,字面)结合,召回更全。 |
|

#### [m1-c4] 全链路逐步详解(重点:每步的取舍 & 翻车点)

### 4.1 切块 chunking
**目的**:块太大→检索到一堆无关内容、还占满上下文;块太小→语义被切断。
**常见策略**:
- **固定长度**:按字符/token 切(最简单)。经验:**300–800 字/块**,**块间重叠 10–15%**(overlap,防止把一句话拦腰切断)。
- **按结构切**:按标题/段落/Markdown 层级切(适合文档、FAQ——你的 FAQ 场景很合适)。
- **递归切(recursive)**:优先按段落,过长再按句子递归细分(LangChain 默认,通用性好)。
- **按语义切**:用模型判断语义边界(效果好但慢、贵)。
**必做**:每个块**带元数据**(来源 URL、标题、市场、时间),生成时能给出处、也能按元数据过滤(比如只查 ES 市场)。
**翻车点**:表格/代码被乱切;忘了 overlap 导致答案跨块丢信息。
### 4.2 Embedding 向量化
**模型选型**:
- OpenAI `text-embedding-3-small`(便宜、够用,1536 维)/ `-large`(更准,3072 维)——你已经在用。
- 开源:`bge-m3`、`bge-large-zh`(中文强)、`m3e`——想省钱/私有化时用。
**要点**:入库和查询**必须用同一个 embedding 模型**;

| 症状 | 根因 | 解法 |
|---|---|---|

#### [m1-c8] 面试高频问答(背这些)

**Q1 什么是 RAG?**
> 让模型先检索后生成:知识库切块做成向量,用户提问时检索最相关片段,再让 LLM 基于片段回答并给出处;既能用私有/最新数据,又能压制幻觉、可溯源。
**Q2 RAG 完整流程?**
> 离线:文档→切块→Embedding→存向量库;在线:问题→Embedding→检索 Top-K→(rerank)→拼 Prompt→LLM 生成带引用;持续:评估检索命中与答案忠实度。
**Q3 检索不准怎么办?**
> 优化切块与 overlap、向量+关键词混合检索、查询改写/HyDE、加 rerank 精排。
**Q4 怎么防幻觉?**
> 强指令"只据资料回答"、设相似度阈值无资料就拒答、降温度、给引用便于核查、上线前用忠实度评估。
**Q5 chunk 怎么定大小?**
> 平衡:太大检索不精+占窗口,太小语义断裂;常 300–800 字 + 10–15% 重叠,FAQ/文档按结构切更好。
**Q6 为什么要 rerank?**
> 向量检索(bi-encoder)快但糙,rerank(cross-encoder)把问题和文档一起打分更准;两阶段"粗召回+精排"兼顾速度与质量。
**Q7 RAG 和微调区别 / 怎么选?**
> 见第 7 节表。知识缺失用 RAG,风格/能力用微调,常结合。
**Q8 怎么评估一个 RAG 系统好不好?**
> 检索侧

#### [m1-c11] 进阶深化 · 检索质量的更多武器（深水区）

上面第 4 章是主干,这里是让检索"再上一个台阶"的高级手段,面试聊到能显深度。
**11.1 相似度度量的门道**
- 常见三种:`余弦相似度`(看方向,最常用)、`点积 dot product`(方向+长度)、`欧氏距离 L2`(看绝对距离)。**向量归一化后,余弦和点积等价**。

**11.2 切块的高级玩法**
- **small-to-big / parent-child(小检索、大喂给)**:用小块做检索(精准命中),但喂给 LLM 时带上它所在的**大块/父段落**(上下文完整)。解决"小块检索准但信息不全"的矛盾。

#### [m1-c12] 生产化考量（上线才知道的坑,PM 尤其要懂）

- **延迟(latency)**:RAG = 检索 + 生成两段耗时。优化:向量检索加索引(HNSW)、rerank 只精排少量、生成用流式输出(先出字)。
- **成本(cost)**:Embedding(建库一次性 + 查询每次)+ LLM 生成(按 token)。优化:**语义缓存**(相同/相似问题直接返回缓存)、精简喂入的块、便宜模型兜底。
- **数据更新 / 增量**:文档变了要重新切块入库;要设计"变更→增量更新索引"流程,别每次全量重建。
- **权限 / 多租户**:不同用户只能检索自己有权看的文档 → 用元数据过滤 + 权限校验(企业级必考)。
- **监控**:记录"检索了什么、命中没、用户满意没、幻觉投诉",持续迭代。
- **安全**:① **Prompt 注入**(用户或文档里藏"忽略以上指令"→ 要隔离/清洗);② **数据泄露**(别把不该检索的私密内容喂进去);③ 输出合规审查。

#### [m1-c13] 高级架构（知道名字 + 一句话原理,面试能接话）

- **CRAG(Corrective RAG)**:检索完先自评质量,差就触发重检索/上网搜。
- **Self-RAG**:模型自己决定"要不要检索、检索够不够、要不要再查"。
- **RAPTOR**:把文档做成**树状层级摘要**,既能答细节也能答"整体讲了啥"。
- **GraphRAG**:结合知识图谱,擅长"关系类、多实体"的复杂问答。
- **Agentic RAG**:检索变成 Agent 的一个"工具",由 Agent 规划多轮检索(和 M2 打通,是趋势)。
- **Multi-hop(多跳)**:答案需要跨多篇资料串联推理(如"A 的老板的公司在哪")。

#### [m1-c14] 产品经理视角（★ 你的重点:别只当技术,要会定义产品）

面试 AI PM,光懂技术不够,得能回答"**这个 RAG 产品怎么算成功、怎么落地**":
- **成功指标怎么定**:业务指标(问题解决率、人工工单下降率、用户满意度)> 技术指标(命中率、忠实度)。技术指标是手段,业务指标是目的。
- **冷启动**:知识库空/少时体验差 → 先覆盖高频问题、给示例问题引导、明确"能答什么范围"。
- **"查不到"的体验设计(关键!)**:宁可**诚实说"资料里没有"**,也不要瞎编;可引导转人工、或问得更具体。**拒答能力是 RAG 产品的护城河,不是缺陷。**
- **成本 × 体验权衡**:要不要 rerank、K 取多大、用哪个模型 —— 都是"多花钱换多少体验提升"的产品决策,要能算账。
- **护栏与合规**:防注入、防泄露、敏感问题拒答、输出免责声明。
- **什么时候"不该用 RAG"**:答案不在文档里(该用工具调用/查数据库)、需要实时计算(该用 Agent+API)、纯闲聊(直接 LLM)。**知道边界 = 成熟度。**
- **迭代闭环**:用户反馈 → 找出高频"答错/答不出" → 补语料 or 调检索 → 回归评估。

### 模块 M2 · Agent

#### [m2-c1] 为什么需要 Agent（先讲清"痛点"）

普通 LLM（哪怕加了 [[M1-RAG|RAG]]）本质还是"**问一句、答一句**"：
1. **不能动手**：只会生成文字，不能查数据库、调 API、发消息、跑代码。
2. **不能多步**：复杂任务（"查出上月 ES 市场跌幅最大的 10 个页面并生成优化建议"）需要多步骤、还要根据中间结果决定下一步——单次问答做不到。
3. **不能自主决策**：遇到"该查哪个库、要不要再查一次、信息够不够"这类判断，它不会自己规划。
> 🎯 一句话：**RAG 让模型"知道得更多"，Agent 让模型"能动手做事"。**
**Agent = 能自主规划 + 调用工具 + 带记忆的 LLM 应用。** 你给它一个目标，它自己拆步骤、选工具、看结果、再决定下一步，直到把事办完。
> 🎯 类比：LLM 是"只会答题的学霸"；Agent 是"给他电脑、搜索引擎、计算器，让他自己查资料、算数、写报告交差的实习生"。

#### [m2-c2] 全貌图（Agent 的运转循环）

一个完整 Agent 由 4 大件组成：
- **大脑（LLM）**：负责推理、决策、生成。
- **工具（Tools）**：它能调用的"手脚"——查库、搜索、发消息、算数、调你写的任何函数。
- **记忆（Memory）**：短期（本轮对话上下文）+ 长期（历史/知识库，常用 [[M1-RAG|RAG]] 实现）。
- **规划（Planning）**：把大目标拆成子步骤，决定先做什么后做什么。

#### [m2-c4] 全链路逐步详解（重点：原理 & 翻车点）

### 4.1 Function Calling / 工具调用（Agent 的地基）
**怎么工作**：
1. 你把可用工具的"说明书"（名字、功能、参数 schema）告诉模型。
2. 模型判断需要用工具时，**不直接答**，而是输出一段结构化调用意图，如 `search_db(market="ES", metric="ctr", limit=10)`。
3. **你的程序**真正执行这个函数，把返回结果喂回模型。
4. 模型基于结果继续（可能再调工具，或给最终答案）。
**要点**：模型只"决定调什么"，**真正执行永远是你的代码**——这就是加护栏的地方（见 4.6）。
**翻车点**：工具描述写不清 → 模型乱调/传错参；工具太多 → 模型选择困难（一般单 Agent 控制在 ~10 个工具内，多了拆多 Agent 或分层）。
### 4.2 ReAct 循环（推理+行动）
不是一次调完，而是"想一步→做一步→看结果→再想"，直到完成。让 Agent 能处理"依赖中间结果"的任务。
**翻车点**：**死循环 / 反复调同一个工具**——必须设**最大步数上限**兜底；某步失败要能重试或换路。
### 4.3 Planning（规划）
- **先规划后执行**：先让 LLM 列出完整步骤计划，再逐步执行（适合流程清晰的任务）。

#### [m2-c5] Agent vs 工作流 vs RAG（★面试最爱问的辨析）

| | 普通工作流（Workflow） | Agent |
|---|---|---|
| 路径 | **人预先定死**每一步 | **模型自主决定**下一步 |
| 灵活性 | 固定，可预测、可控 | 灵活，能应对没预设的情况 |
| 适合 | 流程稳定、步骤明确的重复任务 | 步骤不定、需临场判断的任务 |

> "**不是所有场景都该上 Agent。** 流程固定的用工作流更稳更省；只有当'下一步该做什么'需要模型临场判断时，Agent 才划算。我做的很多 n8n 流程其实是**确定性工作流**，我会诚实区分'哪些是工作流、哪些真的需要 Agent 自主性'——知道边界是成熟度。"
- **Agent vs RAG**：RAG 是"检索资料辅助回答"，是 Agent 可以调用的**一个工具/一种记忆**。Agent 更大，RAG 是它的一块。进阶叫 **Agentic RAG**（Agent 自主决定要不要检索、检索几次、查哪个库）。

### 模块 M3 · Eval

#### [m3-c1] 为什么 AI 一定要评测（先讲清"痛点"）

传统软件是**确定性**的：输入 A 永远输出 B，写单元测试断言相等即可。
大模型是**非确定性**的：
1. **同一个问题，两次回答可能不一样**（还受温度、模型版本影响）。
2. **没有唯一正确答案**（"这段文案质量好不好"没有标准答案）。
3. **改一点就可能全盘变化**：换模型、改 prompt、调参数——你以为在优化 A，可能悄悄弄坏了 B。
> 🎯 一句话：**不评测的 AI 功能 = 蒙着眼睛上线**。你不知道它现在多准、也不知道每次改动是变好还是变差。
**Eval 解决的本质**：给非确定性的 AI **建立可量化、可回归的质量标尺**，让"好不好""改动有没有变好"从拍脑袋变成看数字。
> 🎯 贴你背景：你在数据治理项目做的 **"程序规则基线 XX% → LLM 大幅提升"**、以及"样本对标验证"，本质就是 eval——用一个基线和一批标杆样本去量化"到底提升了多少"。你早就在做 eval，只是没用这个词包装。

#### [m4-c5] 指标体系（★ 从运营到产品最该补的语言）

### 5.1 北极星指标（North Star Metric）
- 一个**最能代表产品核心价值**的指标，全团队对齐它。
- 例：内容平台看"内容消费时长"，电商看"完成购买数"。
- **反例**：别选"虚荣指标"（注册数好看但不代表价值）。
### 5.2 AARRR 海盗模型（用户全生命周期）
| 阶段 | 含义 | 例子指标 |
|---|---|---|
| **Acquisition 获取** | 用户从哪来 | 流量、新增（你的 SEO 增长在这层）|
| **Activation 激活** | 第一次体验到价值 | 完成关键动作率 |
| **Retention 留存** | 会不会再来 | 次日/7日/30日留存 |
| **Revenue 收入** | 怎么变现 | 付费率、客单价（你 SEO 收入 $40→$200 在这层）|
| **Referral 传播** | 会不会推荐 | 分享率、邀请数 |
### 5.3 指标设计原则
- **可量化、可归因、能指导行动**；区分**先导指标**（早期能看、可干预）vs **结果指标**（滞后）。
- **一个目标配一个核心指标 + 几个护栏指标**（防止优化 A 弄坏 B，思路同 [[M3-Eval]] 的回归）。

### 模块 M5 · 大模型八股

#### [m5-c1] 大模型是什么 / 怎么来的（一段话讲清）

大语言模型（LLM）本质是**预测下一个词**的超大神经网络（Transformer 架构）。训练分两大步：
1. **预训练（Pre-training）**：喂海量文本，学"接下来最可能是什么词"，习得语言和世界知识。得到"基座模型"。
2. **后训练/对齐（Alignment）**：让它听话、有用、安全。包括：
   - **SFT（监督微调）**：用"指令→理想回答"的数据教它按指令答。
   - **RLHF（人类反馈强化学习）**：让人给回答排序，训练模型更符合人类偏好。（新变体：DPO 等，知道名字即可）
> 🎯 一句话：**预训练学知识，SFT+RLHF 学"怎么好好说话、听指令、守安全"。**

| 概念 | 通俗解释 |
|---|---|
| **Token** | 模型处理文本的最小单位，≈词/字的碎片。1 个汉字≈1-2 token，1 个英文词≈1-1.5 token。**计费和上下文长度都按 token 算。** |
| **上下文窗口（Context Window）** | 一次能"读"的最大 token 数（输入+输出）。超了要截断/摘要（接 [[M1-RAG]] 为什么要切块）。 |
| **参数量（如 7B/70B）** | 模型规模，B=十亿。越大通常越强但越贵越慢。 |
| **温度（Temperature）** | 控制随机性：低（0~0.3）稳定保守、适合抽取/分类；高（0.7+）发散有创意、适合创作。 |
| **Top-p / Top-k** | 另一种控制输出多样性的采样参数（知道即可）。 |
| **幻觉（Hallucination）** | 不知道也硬编。缓解：RAG 给依据、降温度、拒答、eval。 |
| **对齐（Alignment）** | 让模型行为符合人类意图和价值观。 |
| **涌现能力（Emergent）** | 规模大到一定程度突然出现的新能力（如推理）。 |
| **多模态（Multimodal）** | 能处理文本+图像+音频等（如 GPT-4o、Gemini）。 |

#### [m5-c3] RAG vs 微调 vs 提示工程（怎么选，面试爱问）

| 手段 | 解决什么 | 成本 | 何时用 |
|---|---|---|---|
| **提示工程（Prompt）** | 引导现有模型更好发挥 | 最低 | 首选，先榨干 prompt |
| **RAG** | 知识"不知道"（私有/最新数据） | 中，灵活实时 | 见 [[M1-RAG]] |
| **微调（Fine-tuning）** | 能力/风格不对（语气/格式/专门任务） | 高，需数据算力 | 前两者不够时 |
> **口诀**：**能 prompt 解决不 RAG，能 RAG 解决不微调；知识缺失用 RAG，风格能力用微调，三者常结合。**

**Q1 大模型怎么训练出来的？**
> 预训练学语言和知识（预测下一个 token）→ SFT 教它按指令答 → RLHF 用人类偏好对齐，让它有用、听话、安全。
**Q2 什么是 token？为什么重要？**

**Q3 温度参数怎么调？**
> 控随机性：抽取/分类/要稳定用低温(0~0.3)；创作/头脑风暴用高温(0.7+)。我做质检/抽取都用低温保证一致。
**Q4 为什么会幻觉？怎么缓解？**
> 模型本质是预测下一个词、不知道也会硬接；缓解靠 RAG 给依据、降温度、无资料拒答、上线前 eval（[[M3-Eval]]）。
**Q5 RAG 和微调怎么选？**
> 知识缺失用 RAG（实时灵活），风格/能力不对用微调（成本高），能 prompt 解决就先 prompt，三者常结合。
**Q6 开源和闭源模型怎么选？**
> 闭源强省心但贵+数据外发；开源省钱可私有化可微调但要运维。看预算、数据敏感度、效果要求——我实际做过多模型动态切换和本地部署。

### 模块 M6 · AI-SEO-GEO

#### [m6-c1] 为什么"SEO 正在被 AI 改写"（先讲清变化）

**传统 SEO**：用户在 Google 搜 → 看到蓝色链接列表 → 点进你的网站。你优化的目标是"**排进前几名、拿到点击**"。
**正在发生的变化**：
1. **AI 概览（AI Overviews / SGE）**：Google 搜索结果顶部直接给 AI 生成的答案，用户不点链接就走了 → "**零点击搜索**"暴涨。
2. **AI 搜索/问答工具崛起**：ChatGPT、Perplexity、Gemini、Claude 直接回答问题并"引用来源"，成了新的流量入口。
3. **结果**：传统"排名第一"的价值被稀释；新的战场是——**怎么让 AI 在它的答案里引用你、推荐你**。
> 🎯 一句话：SEO 的目标正从"**被搜索引擎排名**"扩展到"**被 AI 引用和推荐**"。这就催生了 GEO。
---

#### [m6-c2] 核心新概念：GEO / AEO（面试关键词）

| 概念 | 全称 | 通俗解释 |
|---|---|---|
| **SEO** | Search Engine Optimization | 传统搜索引擎优化，目标是排名+点击。 |
| **GEO** | Generative Engine Optimization | **生成式引擎优化**：优化内容让它更容易被 AI 搜索（ChatGPT/Perplexity/AI Overviews）**引用、采纳**。 |
| **AEO** | Answer Engine Optimization | 答案引擎优化，和 GEO 高度重叠，强调"成为 AI 答案的来源"。 |
**GEO 和 SEO 什么关系？**
> 不是取代，是**叠加**。好的 SEO 基础（权威、结构清晰、内容优质）依然是 GEO 的地基；GEO 在此之上额外优化"**易被 AI 理解和引用**"的特性。

#### [m6-c3] AI 搜索的底层原理（懂这个才知道怎么优化）★

AI 搜索工具（Perplexity、AI Overviews）本质就是一个 **[[M1-RAG|RAG]] 系统**：
**这意味着**：要被 AI 引用，你的内容得先"**被检索到**"、再"**被模型选中当依据**"。所以优化方向就清晰了：
- 让内容**语义清晰、直接回答问题**（模型好提取）→ 你做过的 **query-页面语义相似度检测**正是判断"内容和问题匹配度"，直接对应这一步！
- 让内容**结构化、有明确事实和数据**（模型爱引用有出处、有数字的）。
- 让来源**权威可信**（E-E-A-T）。
> 🎯 贴你背景：你早就在用 Embedding 做"query 与页面相似度"——那正是 AI 搜索检索环节的核心逻辑。你不是"追 GEO 热点"，是**本来就在做 GEO 的底层工作**。

#### [m6-c4] GEO 实操：怎么让内容更容易被 AI 引用

| 手段 | 说明 |
|---|---|
| **直接回答式写法** | 段首先给结论/定义（金字塔结构），别绕弯——模型爱提取能直接答问的句子。 |
| **结构化内容** | 清晰标题层级、FAQ 块、列表、表格；便于模型切块（[[M1-RAG#4.1 切块 chunking\|chunking]]）和提取。 |
| **结构化数据（Schema）** | 加 JSON-LD 标记（FAQ、Product、Article…），机器可读。 |
| **具体事实 + 数字 + 出处** | 模型倾向引用有数据、可核查的内容，而非空泛描述。 |
| **权威信号（E-E-A-T）** | Experience/Expertise/Authoritativeness/Trust：作者、引用、更新时间。 |
| **覆盖长尾问句** | AI 搜索多是口语化完整问句 → 内容要覆盖"用户会怎么问"的自然语言。 |
| **多平台存在** | 被 Reddit/维基/知识库等高权威源提及，会提升被引用概率。 |
**FAQ 尤其重要**：AI 搜索天然偏爱"问-答"结构 → **你做过的 FAQ 配备/自动化，正是 GEO 最对口的资产。**

#### [m7-c1] 核心指标概念（会讲、会区分）

| 概念 | 说明 |
|---|---|
| **绝对值 vs 比率** | 别只看总量，要看率（转化率、留存率）——率才可比、能归因。 |
| **先导指标 vs 结果指标** | 先导（可早期干预，如加购率）→ 结果（滞后，如 GMV）。优化要盯先导。 |
| **北极星 + 护栏指标** | 一个核心指标 + 几个不能被牺牲的护栏（如提转化但不能拉高退款率）。 |
| **虚荣指标** | 好看但不代表价值（如注册数、PV）——要警惕。 |
| **同比/环比** | 环比=跟上一期比；同比=跟去年同期比（排除季节性）。 |

#### [m7-c2] 两个必懂模型

**转化漏斗（Funnel）**
> 用户从进入到目标的每一步转化率，找"漏得最多"的一环去优化。
> 例：曝光 → 点击 → 详情页 → 加购 → 下单，哪一步掉得狠就先攻哪。你的 SEO 增长（流量→转化→收入）就是漏斗思维。
**留存曲线（Retention）**
> 次日/7日/30日还回来的用户比例，衡量产品是否真有价值。留存差，拉再多新也白搭。
---

#### [m7-c3] A/B 测试（简单实验思维）★ 面试爱问

- **是什么**：把用户随机分两组，A 用旧版、B 用新版，比核心指标差异，判断改动是否真有效。
- **关键**：① **随机分组**（避免偏差）；② **一次只改一个变量**（否则不知道是谁的功劳）；③ **看统计显著性**（别被随机波动骗，样本要够）；④ 设**护栏指标**防按下葫芦浮起瓢。
- **和 [[M3-Eval]] 的关系**：AI 功能上线也用 A/B——新旧模型/prompt 各分流量比业务指标。灰度是它的保守版。

#### [m7-c5] 分析方法论（讲"怎么用数据做决策"）

- **拆解**：一个大指标掉了 → 拆维度（市场/渠道/时间/人群）定位到底哪块出问题。
- **对比**：有对比才有结论（时间对比、分组对比、对标基线——同 [[M3-Eval]] 思路）。
- **假设驱动**：先有假设（"ES 转化低是因为落地页慢"）再用数据验证，别漫无目的捞数。
- **数据 → 洞察 → 行动**：分析的终点是**能指导做什么**，不是一堆图表。

**Q1 一个核心指标突然下降，你怎么排查？**

### 考点一：Agent 的异常设计（不是任务拆解，是出错怎么办）
**面试官原题**
> ① 用户提出复杂任务后，Agent 如何判断要不要调用工具？
> ② 执行中出现参数缺失、调用失败、结果错误，怎么设计重试和兜底？
> ③ 多轮任务上下文丢失、执行中断怎么办？
**半吊子答案**：任务拆解 → 调用工具 → 返回结果。（只讲了 happy path，一个异常场景都没有）
**该怎么答**
**① 要不要调工具 —— 这是个产品决策，不是模型自由发挥**
- 工具描述（name / description / 参数 schema）写清**触发边界**，明确"什么情况不要调我"；
- 意图分流：闲聊/常识 → 直接答；涉及**实时、私有、可写**数据 → 必须调工具；
- 高风险工具（写库、发消息、付款）**不给模型自主权**，走确认态由用户点确认；
- 兜底：模型判断不了就**问用户一句**，比乱调工具强。
**② 三类异常，三套处理（这是拉开差距的地方）**
| 异常类型 | 根因 | 处理策略 |
|---|---|---|
| **参数缺失/非法** | 用户没说清 or 模型抽错 | schema 校验拦在调用前 → 让模型带**错误信息重填一次** → 仍缺就**反问用户**（"你要查哪个月的？"），绝不瞎填默认值 |
| **调用失败**（超时/限流/5xx）

#### [m9-c3] Tool —— Tool Call / 权限 / 幂等 / Retry

### 三句话讲清
1. **工具按副作用分三级**：只读 / 可写可回滚 / 不可逆——**级别决定要不要 HITL**，这是权限设计的起点。
2. **模型只输出"想调什么"，真正执行永远在代码侧**——所以校验、权限、幂等、重试全部加在代码侧，**不靠 Prompt 求它别乱来**。
3. **可重试与不可重试必须分开**：超时/限流/5xx 值得退避重试；参数错、鉴权失效、额度耗尽重试一百次也一样，还要付钱。
### SEO Agent 里长什么样
| 工具 | 级别 | 设计要点 |
|---|---|---|
| GSC API 取数 | 只读 | 有配额限制 → 按站点/日期批量取 + **缓存**，别逐页调 |
| 页面内容抓取 | 只读 | 超时短、失败可跳过，单页失败不该拖垮整批 |

#### [m9-c4] Memory & State —— 短期 / 长期 / Checkpoint / Resume

### 三句话讲清
1. **Memory 和 State 是两件事，别混**：**Memory 是"记得什么"（内容），State 是"做到哪"（进度）**。面试里能把这两个词分开讲，就已经在多数人之上。
2. **State 必须存在外部**（DB / 任务表），**绝不能只存在对话上下文里**——上下文会被截断，DB 不会。
3. **有了 State 才有三件事**：中断能续跑、失败能按原因归因、进度对人可见。
### SEO Agent 里长什么样
- **短期**：当前这个页面的诊断上下文（指标 + 抓到的内容 + 已经查过什么）；
- **长期**：**"哪类改动真的带来提升"的经验沉淀**——比如"这个站点上，给 title 加数字对 CTR 提升明显、加疑问句没用"；下次诊断相似页面时检索出来注入。**这是 Agent 越用越准的地方，也是产品的复利。**
- **State**：一页一行状态（待诊断 / 诊断中 / 已出建议 / 待人工确认 / 已执行 / 失败带原因）；跑 1000 页中断了只跑未完成的；运营能看到"1000 页完成 987，失败 13，原因分别是……"

#### [m9-c5] Reliability —— 异常 / Fallback / HITL / Guardrail / Observability

### 三句话讲清
1. **兜底有顺序**：**前置校验 → 自动重试 → 降级 → 人工接管**。答"报错重试"只有第一层，答"优化 Prompt"一层都没有。
2. **核心原则：宁可明确失败，也不要静默给错答案。** *"这个我查不到，帮你转人工"是好体验，编一个数字是事故。*
3. **Observability 是 PM 该要的东西**：没有 trace 和失败分桶，你根本不知道该优化哪一环——**这是把"感觉不太行"变成"第 3 桶占 60%"的唯一办法**。
### SEO Agent 里长什么样
> "上一轮面试官问我 **GSC 数据缺失怎么办**，我的完整答案就是这张图：
> **先降级**——找存档数据或替代数据源（比如内部埋点、Bing Webmaster）；
> **能跑的继续跑**——不要因为一个数据源缺失就整批失败，把依赖该数据的诊断标为"数据不足"，其余页面照常；
> **实在不行 HITL**——告警给运营，并且**明确告诉他现在做到哪一步、哪些页面还没诊断**；
> **保存状态**，数据恢复以后从断点续跑，不重头来。"
> 🎯 上一轮这题答得好，被评为"已经是生产级思路"——**这是现成的加分弹药，务必背熟**。

#### [m9-c6] Evaluation —— Business / Quality / Cost / Reliability

### 三句话讲清
1. **四层顺序不能反**：业务价值是目的，质量/成本/可靠性是手段——**"技术指标漂亮但业务没变化"等于没做**。

3. **单一指标必配护栏**：*每次答案都很准，但一次任务 $8、跑 20 分钟、30% 时间 API 报错 → **照样不能上线**。*

#### [q-896a8cf8] （M1）什么是 RAG？

先检索后生成：知识库切块做向量，提问时检索最相关片段，让 LLM 基于片段回答并给出处；用私有/最新数据 + 压幻觉 + 可溯源。

#### [q-17315e50] （M1）检索不准怎么办？

优化切块与 overlap、向量+关键词混合检索、查询改写/HyDE、加 rerank。

#### [q-948f12db] （M1）怎么防幻觉？

强指令"只据资料答"、设阈值无资料就拒答、降温度、给引用、上线前测忠实度。

#### [q-c9d8bd06] （M1）RAG vs 微调怎么选？

知识缺失用 RAG，风格/能力用微调，常结合。

#### [q-5e02ed4f] （M1）BM25 和 TF-IDF 差在哪？

多两件事：**词频饱和**（说 5 次不等于相关 5 倍，`tf(k1+1)/(tf+k1)`，k1≈1.2）和**长度归一**（长文档天然易命中，除以 `1-b+b·len/avglen`，b≈0.75）。BM25F 再加一层字段加权——标题命中比正文命中更说明相关。

#### [q-cf651709] （M1）IDF 到底解决什么问题？

通用词的票权。同一垂类语料里"产品"每篇都有，TF 会给它满分但它没有区分力；`idf=ln(1+(N-n+0.5)/(n+0.5))` 让稀有词权重高出一两个数量级（我实测 12 条语料里"产品" idf≈0.04、"兼职"≈2.12，差 50 倍）。

#### [q-73e1c701] （M1）查询扩展怎么做，坑在哪？

用同义词典把"同一能力的其它说法"加进查询，权重要压低（推测来的证据不能和用户原话等权）。★坑：扩展词必须**整体当短语**匹配，拆成 n-gram 会引入通用词噪声——我实测因此把一个兼职岗排到了第一名。

#### [q-9d8cf256] （M1）什么时候才该上向量检索？

把它写成可判定的条件而不是感觉：语料规模（我定的是约 500 条）、评测集里出现"同义词典补不上"的失败、或 recall 跌破阈值。在那之前关键词方案的召回可能已经够，而向量要付 embedding 调用 + 索引维护 + 冷启动必须先配 Key。

#### [q-cfb28c1b] （M2）什么是 Agent？

能自主规划+调工具+带记忆的 LLM 应用；给目标它自己拆步骤、选工具、看结果、决定下一步。四件套：LLM+工具+记忆+规划。

#### [q-f0c387bb] （M2）Agent vs 工作流？

工作流每步人定死、可预测；Agent 模型自主决定、更灵活但需护栏。流程固定用工作流，需临场判断才上 Agent。

#### [q-d1d8bd0c] （M2）MCP 是什么？

统一的工具接入标准，像 AI 工具界的 USB-C，一次封装处处可用。

#### [q-fcaef232] （M2）Agent 跑偏怎么办？

权限最小化、关键动作人在环、步数/成本上限、防注入、trace 可观测。

#### [q-7e02c6ad] （M3）为什么 LLM 要专门评测？

输出非确定、无唯一答案、改一处可能坏一片；不评测=蒙眼上线。

#### [q-5b834245] （M3）怎么评一个 AI 功能？

建标杆集→定场景指标→规则/LLM-judge/人工打分→比基线→灰度+监控+补 bad case 闭环。

#### [q-60889a6f] （M3）LLM-as-judge 靠谱吗？

能规模化判主观质量但有偏见（位置/长度/自我偏好）；给清晰 rubric、成对比较、人工校准。

#### [q-3a468aa5] （M3）怎么防放量翻车？

离线标杆集回归→灰度小流量→线上监控+报警→bad case 回补。

#### [q-2c726f7e] （M3）技术指标 vs 业务指标？

技术是手段、业务是目的；命中率高但工单不降就没价值。

#### [q-7244257e] （M3）badcase 和 bug 有什么区别？

bug 是代码行为不符合设计；badcase 是**输出不符合预期，但代码可能完全按设计在跑**。所以 badcase 修不了"改一行代码"，要走"收集 → 归类 → 找根因 → 修 → **加进评测集防回归**"的闭环，最后一步最容易被省掉，省掉的结果是同一个 badcase 反复出现。

#### [q-5f607190] （M3）RAG 场景为什么要看 MRR，而不只看 recall？

模型对上下文**开头**最敏感。第一条就命中和第五条才命中，recall 一样但答案质量差很多。MRR = 平均(1÷第一个正确结果的排名) 正是在量这个。

#### [q-ef72ae88] （M3）怎么判断你的评测结论可不可信？

看用例数。我自己的检索评测只有 10 条用例，1 条翻转就是 3~6 个点，所以我不会声称 1.6 个点的提升显著。★ 能主动说出测量的置信度，比报一个漂亮数字更重要。

#### [q-2bd97e12] （M3）举一个"评测集救了你"的例子。

我按教科书把检索打分换成 BM25+IDF，评测显示 recall@3 从 86.7% 掉到 85.0%——12 条语料下 IDF 本身噪声太大。没有评测集，这一版我会直接提交并声称改进了。（详见 [[M3-Eval]] 7.5）

#### [q-34e93c48] （M4）拿到需求怎么做？

先分清需求还是方案，挖真实痛点（用户/场景/痛点+5Why）→ 评优先级 → PRD 定范围和验收 → MVP → 指标验证迭代。

#### [q-c2dab6d8] （M4）怎么定成功指标？

北极星指标代表核心价值 + AARRR 拆全生命周期；核心指标+护栏指标；避免虚荣指标。

#### [q-7094bbde] （M4）优先级怎么排？

RICE 或价值×成本四象限量化，KANO 判惊喜价值，MoSCoW 划版本。

#### [q-2c3c4605] （M4）好 PRD 有什么？

背景目标/用户场景/范围(含明确不做什么)/功能边界异常/原型/验收/指标。

#### [q-37154df0] （M5）大模型怎么训练？

预训练学知识（预测下一个 token）→ SFT 教按指令答 → RLHF 用人类偏好对齐。

#### [q-e4ae4544] （M5）token / 温度？

token 是处理最小单位、计费和上下文都按它算；温度低(0~0.3)稳定适合抽取、高(0.7+)发散适合创作。

#### [q-e2333a2a] （M5）为什么幻觉？怎么缓解？

本质预测下词、不知也硬接；RAG 给依据+降温+拒答+eval。

#### [q-033f6f49] （M5）RAG/微调/prompt 怎么选？

能 prompt 不 RAG，能 RAG 不微调；知识缺失用 RAG，风格能力用微调。

#### [q-14d42793] （M5）开源 vs 闭源？

闭源强省心贵+数据外发；开源省钱可私有化要运维——我做过多模型切换+本地部署。

#### [q-fe86c75d] （M6）AI 时代 SEO 怎么变？

AI 概览/ChatGPT/Perplexity 直接给答案，零点击上升，排名价值稀释；战场从"被排名"扩展到"被 AI 引用"，催生 GEO。

#### [q-2d8d6adf] （M6）什么是 GEO？

生成式引擎优化，让内容更易被 AI 搜索引用；不取代 SEO 是叠加。

#### [q-a788bc16] （M6）怎么让内容被 AI 引用？

直接答问写法、结构化+Schema、给事实数字、E-E-A-T 权威、覆盖口语长尾、多平台提及；FAQ 尤其对口。

#### [q-52a598da] （M6）AI 搜索底层？

本质是 RAG（检索网页→喂 LLM→生成带引用）；所以要被检索到+被选中当依据。

#### [q-5acfd9fd] （M6）AI 大量产内容的风险？

质量滑坡+被降权；配 eval+AI 检测+人工审核+重权威。

#### [q-05e40fe2] （M7）核心指标突然下降怎么排查？

先确认数据无误→拆维度(时间/市场/渠道/人群)定位→形成假设验证→落到可行动结论。

#### [q-3b4553f4] （M7）A/B 测试注意什么？

随机分组、一次只改一个变量、样本量够看显著性、设护栏指标。

#### [q-d627dc57] （M7）什么是好指标？

可量化/可归因/能指导行动/挂业务价值；警惕虚荣指标；看先导+护栏。

#### [q-7c134969] （M8）Agent 怎么判断要不要调工具？

工具描述写清触发边界；实时/私有/可写数据才调；高风险工具不给自主权走确认态；判断不了就反问用户。

#### [q-764ff336] （M8）调用失败/参数缺失怎么办？

三类异常三套解法：参数缺→schema 校验+带错误重填一次+仍缺反问用户；调用失败→区分可重试(超时/429/5xx)与不可重试(400/401)，指数退避最多 2~3 次+步数上限；结果错→结果校验层+交叉验证+低置信转人工。兜底顺序：**重试→降级→人工**。宁可明确失败，不要静默给错答案。

#### [q-042b5f82] （M8）上下文丢失/执行中断？

任务状态与中间结果存外部状态机（不是对话上下文）、按 checkpoint 续跑、步骤幂等、长对话摘要+槽位结构化、超时超步转人工并交接中间结果。（只答"优化 Prompt"=挂）

#### [q-dc7036bf] （M8）RAG 答不准从哪查？

先把召回片段拉出来看：片段里没答案=检索的锅，有答案还答错=生成的锅。再分阶段：查询理解→切分→召回(**Recall@K**)→排序(**MRR/NDCG**)→生成(**忠实度/引用准确率**)。

#### [q-69b5a04c] （M8）怎么管理模型不确定性？

置信度分层（高直接给／中给结果+来源+人工入口／低拒答转人工）+ 三道校验墙（规则→模型→人工）+ 按"错一次代价×概率"决定人在环 + 标注 AI 生成与反馈通道。

#### [q-c23261cf] （M8）效果/成本/延迟怎么取舍？

先由场景定死不可让步项（实时客服延迟优先、离线批处理效果优先、大流量 C 端成本优先），再用模型分级路由+缓存+流式输出找补。

#### [q-238c5aa9] （M8）智能客服上线怎么判断变好？只看准确率够吗？

不够。四层：业务层（任务成功率/**人工接管率**/工单量）、质量层（正确率/忠实度/拒答合理性）、能力层（**工具调用成功率**/平均步数/中断率）、工程层（P95 延迟/Token 成本）。准确率必须和拒答率一起看（拒答 90% 也能刷高准确率）；人工接管率是最诚实的综合指标。

#### [q-27ef8b0d] （M8）Monitoring 和 Eval 有什么区别？

Eval 是上线前的考试（有标杆集、有标准答案、主动跑、回答"能不能上线"）；Monitoring 是上线后的体检（真实流量、没有标准答案、被动观测、回答"是不是正在变坏"）。必须成闭环：离线达标才灰度，线上 bad case 回补标杆集。Agent 场景要做到**步级 trace**，因为路径不唯一，只看"失败了"看不出在哪步失败。详见 [[M3-Eval]] 6.5。

#### [q-5ab2b41a] （M8）怎么做版本对比？

标杆集（高频+长尾+已知 bad case，分层抽样）→ 新旧同题逐条 diff **重点看变坏的** → 灰度 A/B 看业务+护栏指标 → bad case 分桶归因（检索/排序/幻觉/意图/知识库缺失/工具失败）先修最大桶 → 回补标杆集。
