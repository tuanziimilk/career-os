## 第 3 步 · 把 12 条旧记录的键改成新格式（约 5 分钟）

> ⚠️ **这一步 2026-09-16 整个重写过。** 原来写的是「删掉现有的 2 条」，
> 两处都错了，错的过程值得留着：
>
> | 原来写的 | 实际 | 我错在哪 |
> |---|---|---|
> | 「只有 2 条」 | **12 条** | 我看的是 `data/jd_backup.json`（一个旧备份文件），不是插件的实时存储 |
> | 「必须先删再升级，否则云端那条删不掉」 | **什么时候删都删得掉** | `deleteJob()` 写墓碑用的是**记录自己存着的那个 key**（`addTombstone(r.key)`），不是现生成的。所以删旧记录时墓碑记的就是旧键，和云端对得上 |
>
> 两个错都是同一个毛病：**拿手边一份看起来相关的数据当事实，没去查真的那份。**

### 为什么要改

去重键从裸 `12345678` 改成了 `boss:12345678`（为 P6 加猎聘/智联铺路）。
那 12 条是改之前采的，键还是旧的。

**不改也能用** —— 它们同步正常、显示正常。唯一的问题是：
对其中某个岗位**再按一次 `Alt+S`**，新版算出的键是 `boss:xxx`，
和旧记录对不上 → **当成新的插进去，变成两条**。

### 为什么不是「删掉重采」

核过备份数据（12 条）：

| 字段 | 有几条 |
|---|---|
| `status`（投递状态） | **0** |
| `statusHistory`（状态轨迹） | **0** |
| `intent`（意向） | **0** |
| `salaryPending`（薪资待补） | **0** |

**一条都没标记过**，所以「写迁移保住状态」这个理由不成立。
但正文是真金白银 —— 有几条 `body` 两千多字，其中一些岗位可能已经下架，
删了就再也采不回来。所以只改键，不动内容。

### 3.1 先改云端

Supabase → SQL Editor。**先看要动多少行**：

```sql
select count(*) as 待改行数 from career_jds
where user_id = auth.uid() and job_key !~ '^[a-z0-9]+:';
```

数字应该 ≤ 12。确认之后再整段跑：

```sql
begin;
update career_jds
   set job_key = 'boss:' || job_key
 where user_id = auth.uid() and job_key !~ '^[a-z0-9]+:';
update career_status_history
   set job_key = 'boss:' || job_key
 where user_id = auth.uid() and job_key !~ '^[a-z0-9]+:';
commit;
```

> `career_status_history` 那句现在会影响 0 行（没有任何状态记录），
> 留着是因为**顺序上它必须和主表一起改** —— 哪天真有状态了，漏掉这句
> 就会把轨迹变成孤儿。

### 3.2 再改本地

打开插件弹窗 → 在弹窗上**右键 → 检查** → 切到 Console，粘这段：

```js
chrome.storage.local.get({ jds: [] }, (got) => {
  const jds = got.jds || [];
  const before = jds.length;
  let changed = 0;
  for (const r of jds) {
    // 只改「有 jobId、且键还没有前缀」的。URL 降级键不动（它本来就没有 jobId）
    if (!r.jobId || /^[a-z0-9.]+:/i.test(r.key) || /^https?:/i.test(r.key)) continue;
    r.key = "boss:" + r.jobId;
    changed++;
  }
  if (jds.length !== before) { console.error("条数变了，中止，什么都没写"); return; }
  chrome.storage.local.set({ jds }, () => {
    console.log("改了 " + changed + " 条，总数仍为 " + jds.length);
    console.log(jds.slice(0, 3).map((r) => r.key));
  });
});
```

这段在你导出的那份真实备份上**跑过**，结果：

```
改了 12 条 | 总数 12 → 12 ✓ 条数没变
全部变成新键: true    键唯一: true    正文没动: true
第二次再跑改了 0 条 ✓ 幂等
```

它**只在条数没变时才写**，而且可以重复跑（第二次匹配不到，零变化）。
